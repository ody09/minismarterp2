# Reports and Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline with tests first and one final fresh review.

**Goal:** Permission-scoped actual business summaries and reports, with full workflow evidence.
**Architecture:** Read-only BusinessReports service, shared validated ReportPeriod,
report/dashboard controllers and Blade pages; existing account panel retained. Existing
StockBalances and installed Brick Math provide stock and exact monetary arithmetic.
**Tech Stack:** Laravel13/PHP8.4/MySQL8.4, Blade/static CSS, no new dependency.
**Spec:** docs/phase-6.md.

## Global Constraints
- Preserve uncommitted authorized phase5 and existing user data/credentials/custom roles.
- Financial periods use inclusive posting days in Asia/Aden; current month defaults.
- Only confirmed sales/received purchases; exact6-decimal amounts and integer pieces.
- Stock alerts use main warehouse/current day; near-expiry30 default,1..365 selectable.
- No export, valuation/profit, AI, manual opening or stock-count adjustments.

## Review Focus
- FEFO allocations and multi-line documents cannot duplicate financial totals.
- Half-open UTC boundaries must represent inclusive local posting days correctly.
- Summary totals must cover all filtered pages and avoid float/64-bit overflow.
- Dashboard-only/other report permissions must not expose unauthorized business data.
- Zero/inactive/undated/expired/other-warehouse balances must have correct alert status.
